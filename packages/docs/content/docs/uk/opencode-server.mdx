# OpenCode Server

Spleen працює поверх сервера OpenCode. За замовчуванням він сам запускає такий сервер, тож вам нічого робити не доводиться. Ця сторінка потрібна лише тоді, коли ви хочете спрямувати Spleen на сервер, який ви вже запускаєте, або керувати тим, що він запускає.

## Як Spleen знаходить сервер

Коли Spleen стартує, він шукає сервер у такому порядку:

1. повторно використовує сервер, який уже запустив
2. підключається до зовнішнього сервера, якщо ви його налаштували
3. інакше запускає власний сервер і керує ним

За замовчуванням Spleen керує власним сервером на виділеному порту. Порт може змінитися після перезапуску. Spleen не підключається автоматично до іншого сервера OpenCode на порту `4096`.

## Підключення до сервера, який ви вже запускаєте

Задайте це перед запуском Spleen:

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true spleen
```

- `OPENCODE_HOST` — повна адреса вашого сервера OpenCode, разом із портом (значення на кшталт `http://localhost:4096`). У кінці не повинно бути шляху.
- `OPENCODE_SKIP_START=true` — каже Spleen не запускати власний сервер.

Якщо вам потрібно лише змінити порт, задайте `OPENCODE_PORT` замість `OPENCODE_HOST`.

Якщо в `OPENCODE_HOST` бракує порту або є шлях, Spleen ігнорує його й повертається до запуску власного сервера. Слідкуйте за журналами запуску на предмет попередження `[config]`, якщо очікуване підключення не відбулося.

## Керування сервером із CLI

```bash
spleen status
spleen logs
spleen restart
spleen stop
```

`spleen` сам по собі запускає сервер у фоні. Додайте `--foreground`, щоб лишити його прив'язаним до вашого терміналу.

## Запуск Spleen при вході в систему

Скористайтеся `startup enable`, щоб встановити нативний користувацький сервіс. Spleen використовує `launchd` на macOS, `systemd --user` на Linux і Task Scheduler на Windows.

```bash
spleen startup enable
spleen startup status
spleen startup disable
```

Щоб захистити UI, задайте пароль під час увімкнення сервісу:

```bash
SPLEEN_UI_PASSWORD='secret' spleen startup enable
```

Для headless-сервера, який стартує під час входу та використовується desktop або mobile застосунками, додайте `--api-only` і доступний host:

```bash
spleen startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` зберігає знімок поточного середовища в сервісі, щоб запуск був ближчим до ручного запуску `spleen` з тієї самої shell-сесії. Так зберігаються токени провайдерів, `PATH`, налаштування SSH agent та інші CLI-змінні для auth/config. Використайте `--no-env-snapshot`, якщо потрібне мінімальне середовище сервісу.

Startup-сервіс пам'ятає `--port`, `--host`, `--ui-password` і `--api-only`. CLI restart і restart під час оновлення повторно використовують ці збережені налаштування.

Щоб створити link підключення для іншого застосунку Spleen, використайте:

```bash
spleen connect-url --port 3000 --server http://your-host:3000 --qr
```

Запустіть `spleen connect-url --help`, щоб побачити всі опції link, зокрема `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` і `--qr`.

Тунелями для такого запущеного сервісу можна керувати окремо:

```bash
spleen tunnel start --port 3000
spleen tunnel stop --port 3000
```

Зупинка тунелю не перезапускає сервіс або застосунок.

## «OpenCode перезапускається»

Поки сервер запускається або перезапускається, Spleen показує стан «OpenCode перезапускається» і призупиняє запити, доки той не буде готовий. Це нормально одразу після запуску чи перезапуску. Якщо стан так і не зникає, див. [Підключення до OpenCode](/uk/troubleshooting/opencode-connection/).
