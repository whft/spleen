# Змінні середовища

Spleen читає ці змінні під час запуску. Для startup-сервісів `spleen startup enable` типово зберігає snapshot поточного середовища, тому після змін перезапустіть цю команду.

## Змінні для OpenCode, Git і термінала

Щоб передати OpenCode, Git, терміналу та [діям проєкту](/uk/project-actions/) власні змінні, наприклад API-токен чи адресу бази даних, додайте їх у **Налаштування → Загальні → Змінні середовища**, а не експортуйте перед запуском Spleen. Значення лишаються на машині, де працює Spleen, у файлі `environment.json` у директорії даних, і прочитати його може лише ваш користувач. Налаштування більше ніколи не показують значення: його можна замінити або видалити, але не переглянути.

- OpenCode отримує їх під час запуску, тож після змін перезапустіть його. Налаштування пропонують для цього кнопку.
- Змінні, задані через `opencode service set env`, теж доходять до OpenCode. Змінні з Налаштувань мають перевагу.
- Git, термінал і дії проєкту отримують їх під час наступного запуску.
- Змінні, які Spleen задає для самого OpenCode, як-от його пароль і конфігурацію, мають перевагу над вашими.

Проєкт може додати власні змінні або команду, що їх виводить, наприклад `direnv export json`, у **Налаштування → Проєкти**. Див. [Проєкти](/uk/projects/#середовище-проєкту).

Ці змінні не доходять до сервера OpenCode, який ви запустили самі, а в розширенні VS Code такого налаштування немає. Усе, що нижче, Spleen читає сам під час запуску.

## Сервер Spleen

### `SPLEEN_HOST`

Адреса, на якій слухає web-сервер Spleen. Використовуйте `0.0.0.0`, щоб відкрити доступ з інших машин.

### `SPLEEN_LAN_URL`

Адреса, за якою інші пристрої у вашій мережі дістаються до Spleen, наприклад `http://192.168.1.20:3000`. Посилання і QR-коди для підключення пропонують її замість адреси, яку Spleen визначає сам. Задайте її, коли це визначення хибне, наприклад у Docker, де Spleen бачить лише внутрішню адресу контейнера.

### `SPLEEN_UI_PASSWORD`

Пароль для browser UI. Використовуйте його для доступу не лише з localhost, тунелів або reverse proxy.

### `SPLEEN_UI_SESSION_TTL_HOURS`

Скільки годин діє вхід у браузері, якщо «довіряти цьому пристрою» вимкнено. За замовчуванням `12`.

### `SPLEEN_UI_TRUSTED_SESSION_TTL_DAYS`

Скільки днів діє вхід на пристрої, якому ви довіряєте. За замовчуванням `7`.

### `SPLEEN_API_ONLY`

Запускає Spleen у headless mode, якщо встановлено `true` або `1`. API routes залишаються доступними для desktop і mobile clients, але browser UI не віддається.

### `SPLEEN_FRAME_ANCESTORS`

Origins, яким дозволено показувати Spleen у фреймі на своїй сторінці, через пробіл, наприклад `https://dash.example.com`. `*` дозволяє будь-який сайт. Типово вбудовувати його можуть лише сам Spleen і його desktop- та mobile-застосунки, тож інші сайти не можуть перекрити його кнопки.

### `SPLEEN_DATA_DIR`

Перевизначає директорію даних Spleen. Типово це `~/.config/spleen`.

### `SPLEEN_CHATS_DIR`

Переносить директорії керованих чатів, які Spleen створює для чатів без проєкту. Типово це `~/.config/spleen/chats`. Вкажіть директорію, яку може читати сервер OpenCode, якщо Spleen і OpenCode працюють від різних користувачів. Наявні чати не переносяться.

### `SPLEEN_COMPRESS_API`

Керує стисненням API-відповідей. `true` або `1` вмикає, `false` або `0` вимикає.

### `SPLEEN_SKIP_API_COMPRESSION`

Вимикає стиснення API-відповідей, якщо встановлено `true` або `1`. Має пріоритет над `SPLEEN_COMPRESS_API`.

### `SPLEEN_VERBOSE_REQUEST_LOGS`

Вмикає детальні HTTP request logs, якщо встановлено `true` або `1`.

### `SPLEEN_UPDATE_API_URL`

Перевизначає endpoint для перевірки оновлень. Більшості користувачів це не потрібно.

### `SPLEEN_PACKAGE_MANAGER`

Примусово задає package manager для оновлень, якщо auto-detection помилився.

## Проксі

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

Спрямовує власні вихідні запити Spleen, як-от ліміти використання та каталоги скілів, через проксі. Назви в нижньому регістрі теж працюють. Хости з `NO_PROXY` під'єднуються напряму, а `localhost`, `127.0.0.1` і `::1` — завжди, тож зворотні виклики входу та локальний сервер OpenCode працюють як раніше.

## Сервер OpenCode

### `OPENCODE_HOST`

Підключає Spleen до вже запущеного OpenCode server. Значення має бути `http` або `https` origin з явним портом і без path, query або hash. `OPENCODE_HOST` має пріоритет над `OPENCODE_PORT`.

### `OPENCODE_PORT`

Задає порт OpenCode server. Для managed OpenCode це бажаний порт; з `OPENCODE_SKIP_START=true` Spleen підключається до зовнішнього сервера на цьому порту.

### `OPENCODE_SKIP_START`

Не дає Spleen запускати власний OpenCode server, якщо встановлено `true`.

### `SPLEEN_OPENCODE_HOSTNAME`

Hostname для OpenCode server, яким керує Spleen. Типово `127.0.0.1`.

### `SPLEEN_OPENCODE_HEALTH_TIMEOUT_MS`

Граничний час перевірки стану OpenCode у мілісекундах. Типове значення `5000`.

### `SPLEEN_OPENCODE_HEALTH_CONSECUTIVE_FAILURES`

Кількість послідовних зарахованих невдалих перевірок стану, після яких Spleen перезапускає керований процес OpenCode, що досі працює. Типове значення `20`. Зайняті сесії можуть затримати перезапуск.

### `SPLEEN_OPENCODE_HEALTH_INTERVAL_MS`

Перевизначає інтервал перевірки стану керованого OpenCode у мілісекундах. Також задає мінімальний час між зарахованими помилками. Типове значення `0` зберігає серверний інтервал `15000` мілісекунд.

### `SPLEEN_OPENCODE_HEALTH_CACHE_MS`

Час у мілісекундах, протягом якого Spleen повторно використовує результат перевірки стану керованого OpenCode, зокрема невдалий. Типове значення `750`.

### `OPENCODE_BINARY`

Шлях до executable `opencode`, який має запускати Spleen.

### `OPENCODE_CONFIG`

Шлях до конкретного config-файлу OpenCode.

### `OPENCODE_CONFIG_DIR`

Шлях до директорії config OpenCode для agents, skills, snippets і config discovery.

### `OPENCODE_DATA_DIR`

Власна директорія даних для managed OpenCode server.

### `OPENCODE_JWT_SECRET`

Secret для підпису UI auth tokens. Для постійних service deployments використовуйте довге випадкове значення.

## Terminal і Git

### `SPLEEN_TERMINAL_SHELL`

Shell executable для terminal sessions в Spleen.

### `SPLEEN_GIT_BINARY`

Git executable для Git-функцій Spleen.

### `GIT_BINARY`

Альтернативний override для Git executable. Для Spleen-specific налаштувань краще використовуйте `SPLEEN_GIT_BINARY`.

### `SPLEEN_GIT_READ_CACHE_TTL_MS`

TTL у мілісекундах для cached Git-backed file reads. Встановіть `0`, щоб вимкнути cache під час debugging.

## Voice і tunnels

### `OPENAI_API_KEY`

API key, яким голосові функції Spleen користуються, коли звертаються до самого OpenAI. На власний OpenAI-сумісний сервер він ніколи не надсилається: дай цьому серверу окремий ключ у Налаштуваннях.

### `SPLEEN_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Дозволяє remote OpenAI-compatible base URLs для voice-функцій, якщо встановлено `true` або `1`.

### `NGROK_AUTHTOKEN`

ngrok auth token для tunnel-команд Spleen. Також можна налаштувати ngrok через `ngrok config add-authtoken <token>`.

## Runtime helpers

### `BUN_BINARY`

Bun executable, який Spleen має використовувати для запуску daemon processes.

### `BUN_INSTALL`

Корінь інсталяції Bun. Spleen використовує його, щоб знайти `bin/bun` для daemon startup і updates.

### `VITE_OPENCODE_URL`

Build-time API base URL для Vite-built web app. Для звичайного CLI або desktop usage більшості користувачів це не потрібно.
