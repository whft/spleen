# OpenCode Server

Spleen se ejecuta sobre un servidor de OpenCode. De forma predeterminada inicia uno por ti, así que no tienes que hacer nada. Solo necesitas esta página si quieres apuntar Spleen a un servidor que ya ejecutas, o gestionar el que él inicia.

## Cómo encuentra Spleen un servidor

Cuando Spleen arranca, busca un servidor en este orden:

1. reutilizar un servidor que ya inició
2. conectarse a un servidor externo si configuraste uno
3. de lo contrario, iniciar y gestionar su propio servidor

De forma predeterminada, Spleen gestiona su propio servidor en un puerto asignado. El puerto puede cambiar después de reiniciar. Spleen no se conecta automáticamente a otro servidor de OpenCode en el puerto `4096`.

## Conéctate a un servidor que ya ejecutas

Define esto antes de iniciar Spleen:

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true spleen
```

- `OPENCODE_HOST` — la dirección completa de tu servidor de OpenCode, incluido el puerto (un valor como `http://localhost:4096`). No debe tener una ruta al final.
- `OPENCODE_SKIP_START=true` — le indica a Spleen que no inicie su propio servidor.

Si solo necesitas cambiar el puerto, define `OPENCODE_PORT` en lugar de `OPENCODE_HOST`.

Si a `OPENCODE_HOST` le falta el puerto o tiene una ruta, Spleen lo ignora y recurre a iniciar su propio servidor. Observa los registros de arranque por si aparece una advertencia `[config]` cuando una conexión que esperabas no ocurrió.

## Gestiona el servidor desde la CLI

```bash
spleen status
spleen logs
spleen restart
spleen stop
```

`spleen` por sí solo inicia el servidor en segundo plano. Añade `--foreground` para mantenerlo asociado a tu terminal.

## Iniciar Spleen al iniciar sesión

Usa `startup enable` para instalar un servicio nativo de usuario. Spleen usa `launchd` en macOS, `systemd --user` en Linux y Task Scheduler en Windows.

```bash
spleen startup enable
spleen startup status
spleen startup disable
```

Para proteger la UI, define la contraseña al habilitar el servicio:

```bash
SPLEEN_UI_PASSWORD='secret' spleen startup enable
```

Para un servidor headless que arranca al iniciar sesión y se usa desde apps de escritorio o móviles, añade `--api-only` y un host alcanzable:

```bash
spleen startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` guarda una captura del entorno actual en el servicio para que el arranque se parezca más a ejecutar `spleen` desde la misma shell. Así conserva tokens de proveedores, `PATH`, configuración del agente SSH y otras variables CLI de auth/config. Usa `--no-env-snapshot` si quieres un entorno de servicio mínimo.

El servicio de inicio recuerda `--port`, `--host`, `--ui-password` y `--api-only`. El reinicio por CLI y el reinicio durante una actualización reutilizan esos ajustes guardados.

Para crear un enlace de conexión para otra app de Spleen, usa:

```bash
spleen connect-url --port 3000 --server http://your-host:3000 --qr
```

Ejecuta `spleen connect-url --help` para ver todas las opciones del enlace, incluidas `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` y `--qr`.

Puedes gestionar túneles de forma independiente para ese servicio en ejecución:

```bash
spleen tunnel start --port 3000
spleen tunnel stop --port 3000
```

Detener el túnel no reinicia el servicio ni la app.

## "OpenCode is restarting"

Mientras el servidor se inicia o reinicia, Spleen muestra un estado "OpenCode is restarting" y pausa las solicitudes hasta que esté listo. Esto es normal justo después de iniciar o reiniciar. Si nunca desaparece, consulta [Conexión de OpenCode](/es/troubleshooting/opencode-connection/).
